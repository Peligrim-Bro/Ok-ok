# Project decisions and continuation

The owner approved a small durable decision/task journal on 24 October 2026.
`ops/project-memory.json` is private project working context, never public site
content, a user database, a model memory service or permission to act.

At the beginning of project work read `ops/project-memory.json`. Select the
decisions and open tasks relevant to the request, then read their source files.
The next shared-content stage adds an optional local context-report command;
that helper must not be assumed available until its checked release.
Read the cited rules, compare current Git and observed live outcomes, then act
within the owner's current scope. A recorded date is not a fresh source check.

Update stable IDs at milestones and before handoff. Use `in_progress`,
`needs_verification`, `blocked`, `deferred`, or `done`; include the next action
and evidence paths. Mark a release done only after required QA and observed
deployment. Keep decisions short; detailed policies remain in their cited files.
Never store secrets, payment records or private customer/user content here.

Owner exclusions: the catalogue AI/RAG assistant remains deferred until a new
instruction. On 24 October the selfie Tarot idea was also deferred and Windows
Face ID rejected. Adding notes must not reactivate either idea.

This is file-based continuity with an explicit read step. It does not inject
memory into other chats or automatically run agents between conversations.
