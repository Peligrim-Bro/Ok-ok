# OK-OK: правила изменений и публикации

Актуальная сводка на 20.10.2026. Общие инструкции находятся в AGENTS.md, подробные ограничения функций — в docs/FEATURE_RULES.md. Новое прямое решение владельца заменяет старое только по тому же предмету; остальные требования и ранее выданные разрешения сохраняются. История прежних решений доступна в Git.

## Проект и границы работы

- Репозиторий Peligrim-Bro/Ok-ok, ветка main. Хостинг — Cloudflare Worker ok-ok. Netlify не восстанавливать.
- Перед изменениями читать свежий main и сохранять параллельные исправления. Не использовать force push и автоматический откат.
- Оплаты и Telegram не менять без соответствующей задачи. Не удалять историю платежей, отправок и очередь уведомлений. Не раскрывать секреты.
- Не устанавливать новые инструменты лишь из-за их наличия в подборке. Платные сервисы, изменение прав аккаунтов и разрушительные операции требуют разрешения владельца.

## Обязательный порядок выпуска

1. Подготовить изменение от свежего main в отдельной ветке, сохранив чужие правки.
2. Для кода/вёрстки собрать окончательный результат и выполнить native/build-проверки, полный набор браузерных тестов и три запуска Lighthouse ДО обновления main: Cloudflare публикует независимо.
3. Проверить RU/EN/TH, обе темы, телефон/планшет/горизонтальный режим; просмотреть снимки на пересечения, обрезание текста, навигацию, фильтры, закрытие длинных окон и восстановление позиции после чата. Сохранять tests/layout.spec.cjs, tests/author-chat.spec.cjs и остальные регрессионные проверки.
4. Исправить ошибки до выпуска. Если обязательная проверка недоступна — оставить код вне main и назвать конкретный блокер. Не ослаблять проверки и не перекладывать обычную QA на владельца.
5. После публикации подтвердить Workers Builds: ok-ok, точный commit в /build-info.json и результат scripts/verify-live.mjs. Один коммит не доказывает выпуск.

- Изменения ТОЛЬКО документации требуют проверки текста и diff; повторять неизменённые тесты приложения не нужно.
- Сборка npm run build проверяет итоговые файлы через verify-project.mjs и verify-quality.mjs; эти проверки действуют и в native Workers Builds. Команды test:mobile и audit сохраняются.
- GitHub Actions проверяет мобильную вёрстку и offline PWA, Lighthouse выполняется трижды; отчёты хранятся 14 дней. Actions диагностические и не блокируют независимую публикацию Cloudflare. Ошибка проверки сама по себе не доказывает падение сайта.
- quality-budget.json ограничивает несжатый HTML, HTML gzip, весь JS и статический объём; это контроль роста сборки, не начальной загрузки. Lighthouse измеряет загрузку отдельно. Повышать бюджеты только после анализа причин.
- Сохранять Service Worker: уникальный кеш выпуска, network-first навигация, обход /api/. finalize-release-cache.mjs выполняется после патчей; идентичность кеша из build-info.json, не runtime Date.now(). Workbox пока не требуется.
- Эмуляцию экрана и подменённый виджет не выдавать за проверку физического iPhone или настоящего tawk.to. HTTP 200 и наличие настроек не доказывают доставку Telegram.
